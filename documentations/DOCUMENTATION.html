Integration Gateway Service

Spesifikasi Teknis & Dokumentasi API  |  Versi 1.0.0  |  Stack: Node.js, Fastify, MySQL, BullMQ, Redis

Tujuan Service: Memisahkan logika integrasi pihak ketiga dari aplikasi utama (Main App), mencatat seluruh log transaksi secara terpusat, menyediakan mekanisme isolasi kegagalan (Circuit Breaker), serta mengamankan kredensial pihak ketiga dengan enkripsi AES-256-GCM.

1. Arsitektur & Pola Komunikasi

┌──────────────┐     HTTP (x-api-key)     ┌────────────────────────┐      HTTPS / REST      ┌─────────────────┐
│              │ ───────────────────────► │  Integration Gateway   │ ─────────────────────► │  Third-Party /  │
│   Main App   │                          │                        │                        │  External API   │
│              │ ◄─────────────────────── │  - Enkripsi Kredensial │ ◄───────────────────── │  (e.g. Partner) │
└──────────────┘         JSON Response    │  - Circuit Breaker     │      HTTP Response     └─────────────────┘
                                          │  - Queue Background    │
                                          └───────────┬────────────┘
                                                      │
                                           ┌──────────┴──────────┐
                                           │                     │
                                           ▼                     ▼
                                    ┌──────────────┐      ┌──────────────┐
                                    │ MySQL (Logs) │      │ Redis (Queue)│
                                    └──────────────┘      └──────────────┘

Keuntungan Arsitektur:

  • Main App Tetap Ringan: Service utama tidak membengkak karena library/aturan spesifik vendor luar.
  • Zero Re-deploy: Jika vendor ganti base URL atau rotate token, cukup update di database Gateway. Main App tidak perlu di-restart atau di-build ulang.
  • Audit Log & Penanganan Komplain: Bukti request mentah dan balasan dari vendor tersimpan rapi untuk investigasi insiden.
  • Isolasi Downtime (Circuit Breaker): Jika vendor mati total, Gateway memutus loop tunggu sehingga Main App tidak kehabisan connection pool.

2. Standar Autentikasi Internal

Semua endpoint (kecuali /health) mewajibkan header API Key internal:

Header Name Contoh Nilai Deskripsi
x-api-key secretku4t Divalidasi dengan environment variable API_KEYS di file .env Gateway.
Content-Type application/json Format baku pengiriman body request.

3. Spesifikasi Lengkap API & Kamus Data

A. Registrasi Integrasi Baru (POST /integrations)

Mendaftarkan konfigurasi endpoint pihak ketiga ke katalog Gateway.

1. Root Level Request Body

Key Tipe Data Status Pilihan / Contoh Fungsi & Penjelasan
code String REQUIRED "wilayah-id-provinces" Identifier unik (slug: huruf kecil, angka, strip). Dipakai saat pemanggilan execute.
name String REQUIRED "Wilayah ID - Provinsi" Nama deskriptif untuk kemudahan membaca di log dan dashboard monitoring.
direction Enum (String) REQUIRED OUTBOUND (Hit vendor)
INBOUND (Webhook terima)
PASSIVE (Webview / URL)
BILATERAL (Dua arah / WS) 		Arah aliran data. Gunakan OUTBOUND untuk panggil API luar, PASSIVE untuk webview.
transport Enum (String) REQUIRED REST | WEBVIEW | WEBHOOK | SOAP | GRAPHQL Menentukan adapter internal yang akan mengeksekusi integrasi ini.
execution_mode Enum (String) OPTIONAL
Default: SYNC		 SYNC atau ASYNC SYNC untuk request instan (tunggu response). ASYNC untuk antrian BullMQ di background.
config Object REQUIRED (Lihat tabel Config) Objek detail teknis endpoint pihak ketiga (URL, path, timeout, circuit breaker).
credentials Object OPTIONAL (Lihat tabel Credentials) Informasi rahasia autentikasi vendor (otomatis dienkripsi AES-256-GCM ke MySQL).
metadata Object OPTIONAL { "mask_fields": ["rek"] } Pengaturan tambahan, seperti daftar field yang wajib disamarkan di tabel audit log.

2. Isi Objek config (Khusus Transport: REST)

Key Tipe Data Status Contoh Nilai Penjelasan
base_url String (URL) REQUIRED "https://wilayah.id" Host utama API vendor eksternal.
method String REQUIRED GET, POST, PUT, PATCH, DELETE Metode HTTP yang diminta oleh vendor eksternal.
path String REQUIRED "/api/provinces.json"
"/api/regencies/{{prov_id}}.json"		 Path endpoint. Mendukung placeholder {{variabel}} yang akan diisi otomatis dari payload.
headers Object OPTIONAL { "Content-Type": "application/json" } Header statis atau dinamis yang wajib dikirim ke pihak ketiga.
body_template Object OPTIONAL { "account": "{{rekening}}" } Template JSON body jika method POST/PUT. Placeholder akan diisi dari payload.
query_template Object OPTIONAL { "page": "{{page_num}}" } Template query parameter URL (?page=1).
timeout_ms Integer OPTIONAL
Default: 30000		 10000 Batas waktu tunggu koneksi dalam milidetik sebelum dianggap TIMEOUT.
circuit_breaker Object OPTIONAL { "enabled": true, "failureThreshold": 5, "resetTimeoutMs": 30000 } Jika vendor gagal berturut-turut sebanyak failureThreshold, Gateway memutus request selama resetTimeoutMs ms.

3. Isi Objek config (Khusus Transport: WEBVIEW)

Key Tipe Data Status Contoh Nilai Penjelasan
base_url String (URL) REQUIRED "https://partner.com/embed" URL dasar halaman webview yang akan ditampilkan ke pengguna.
url_template String OPTIONAL "{{base_url}}?user={{user_id}}&token={{generated_token}}" Template pembentukan URL akhir beserta query parameter dinamis.
token_generation Object OPTIONAL { "type": "SIMPLE", "secret_field": "secret" } Aturan pembuatan token otomatis (tipe SIMPLE hash atau HMAC) jika vendor butuh signed URL.
iframe_options Object OPTIONAL { "width": "100%", "height": "600px" } Atribut bantuan untuk tim frontend saat me-render iframe/webview di aplikasi.

4. Objek credentials

Key Tipe Data Status Pilihan Nilai Penjelasan
auth_type Enum (String) REQUIRED* NONE (Tanpa auth)
BEARER (Bearer Token)
API_KEY (Custom Header)
BASIC (Basic Auth)
CUSTOM (Header bebas) 		Tipe autentikasi yang diminta pihak ketiga. *Wajib jika credentials disertakan.
data Object REQUIRED* Bearer: { "token": "xyz" }
API Key: { "api_key": "123", "header_name": "X-API-Key" }
Basic: { "username": "admin", "password": "pass" } 		Data rahasia autentikasi. Disimpan dalam bentuk terenkripsi AES-256-GCM.

B. Eksekusi Integrasi (POST /execute/:code)

Endpoint yang dipanggil oleh Main App setiap kali ingin menjalankan integrasi pihak ketiga.

Request Body

Key Tipe Data Status Contoh Nilai Penjelasan Fungsi
payload Object OPTIONAL
Default: {}		 { "province_code": "11", "user_id": "USR-1" } Data dinamis yang akan disuntikkan ke template path, headers, atau body_template yang sudah didaftarkan.
correlationId String OPTIONAL "TRX-20261030-88899" Nomor referensi / Trace ID dari Main App untuk pelacakan silang di log audit. Jika dikosongkan, Gateway akan membuat UUID otomatis.

Struktur Response dari Gateway:

Key Response Tipe Data Penjelasan Nilai
success Boolean true jika pihak ketiga membalas HTTP 2xx. false jika timeout, circuit breaker open, atau HTTP 4xx/5xx.
data Any (Object/Array) Data asli hasil respons dari pihak ketiga dalam format JSON (atau objek URL jika tipe Webview).
metadata.duration_ms Integer Durasi waktu respons jaringan vendor pihak ketiga dalam milidetik (latency).
metadata.statusCode Integer Status HTTP asli yang dikembalikan oleh server vendor (misal: 200, 400, 502).
metadata.correlationId String Trace ID yang sama dari Main App untuk kebutuhan audit.
error Object / Null Berisi detail error jika pemanggilan gagal.

{
  "success": true,
  "data": {

      { "code": "11", "nama": "Aceh" },

6. Fitur Keandalan (Reliability Features)

Fitur Mekanisme Teknis Manfaat untuk Sistem
Circuit Breaker State CLOSED → OPEN otomatis jika 5 kali gagal berturut-turut. Mencegah Main App hang menunggu vendor yang sedang down total.
Asynchronous Queue BullMQ + Redis worker terpisah (worker-runner.js). Menangani integrasi dengan pemrosesan berat / batch tanpa memblokir koneksi HTTP Main App.
AES-256-GCM Encryption Enkripsi simetris dengan Auth Tag & random IV untuk setiap kredensial di database. Jika database bocor, kredensial dan token rahasia pihak ketiga tetap aman dan tidak bisa dibaca.
Sensitive Data Masking Penyaringan otomatis field sensitif (password, token, rekening) sebelum ditulis ke log. Kepatuhan privasi data dan perlindungan informasi sensitif pada log sistem.
